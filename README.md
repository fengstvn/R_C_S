红色文化学习打卡系统
  基于 Python + Tkinter + SQLite 的红色文化学习打卡平台（可视化单机版）
一、项目简介
本系统面向高校学生与管理人员，通过 "景点浏览 — 学习打卡 — 积分激励" 的方式引导学生主动学习红色文化、传承革命精神。系统采用单机桌面应用形态，数据以 SQLite 文件形式持久化在本地，首次运行自动建库并写入示例数据，无需任何额外配置。
系统包含两类角色：
- 学生用户：注册登录后可浏览公告与景点、进行学习打卡、管理自己的打卡记录与个人信息；
- 管理员：系统内置账号（不存入数据库），负责公告与景点的维护、用户查看。

五、数据库设计
四张数据表，外键级联删除，关键查询列已建索引：
      表
      说明
      关键约束
      users
      注册用户（密码加盐哈希存储）
      username 唯一
      places
      景点（含热门标记、打卡计数）
      打卡次数 ≥10 自动置 is_hot=1
      records
      打卡记录（用户与景点的多对多联系）
      UNIQUE(user_id, place_id) 防止重复打卡；外键级联删除
      notices
      系统公告
      —
安全与一致性设计
- 密码安全：SHA-256 加盐哈希（随机盐 Base64 编码），数据库不存明文密码；
- 事务一致性：打卡时"插入记录 + 用户积分 +1 + 景点打卡次数 +1"在同一数据库事务中完成，删除打卡同样在事务内回退积分，任一环节失败整体回滚；
- 防重复打卡：数据库唯一约束 + 业务层双重校验；
- 并发加固：数据访问层启用 WAL 日志模式与 10 秒忙等待超时，消除多连接写锁冲突。
六、接口测试模式
为便于使用 Postman / JMeter 进行接口与性能测试，系统提供了基于 Flask 的本地 HTTP 接口层（api_server.py），业务逻辑与桌面版完全复用同一 DatabaseManager：
pip install flask   # 接口模式需要
python api_server.py
提供的主要接口：/api/register、/api/login、/api/notices、/api/places、/api/places/hot、/api/checkin、/api/records。
